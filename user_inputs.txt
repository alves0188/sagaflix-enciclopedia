BOOKFLIX

Documento de Estrutura Técnica e Produto


Versão 1.0  ·  Confidencial
 
1. Visão Geral do Produto
O BookFlix é uma plataforma SaaS de leitura digital com modelo similar ao Netflix, porém voltado para autores independentes e leitores. A plataforma opera com três perfis distintos de usuário, cada um com sua própria interface, permissões e experiência — mas todos conectados à mesma base de dados e API central.

O diferencial central do produto é a separação radical entre a experiência de quem cria (autor), de quem administra (admin master) e de quem consome (leitor). Não se trata de um CMS com área pública: são três produtos distintos que compartilham infraestrutura.

1.1 Os três perfis da plataforma

Admin Master	Autor	Leitor
Proprietário da plataforma	Criador de conteúdo	Consumidor de conteúdo
Acesso total a tudo	Acesso ao próprio painel	Acesso à vitrine e leitor
Pode editar qualquer autor	Cadastra e publica obras	Lê, avalia, bookmarks
Gerencia planos e usuários	Acompanha métricas	Recebe recomendações
Vê dados financeiros	Configura perfil público	Experiência premium

 
2. Arquitetura Técnica
A plataforma deve ser construída com uma arquitetura desacoplada: um backend/API único que serve os três frontends de forma independente. Isso permite escalar cada interface separadamente, além de manter a segurança por camadas de permissão.

10. Glossário e Convenções

Convenções de nomenclatura a seguir em todo o projeto:

•	Banco de dados: snake_case (user_id, created_at, is_active)
•	API (JSON responses): camelCase (userId, createdAt, isActive)

•	Componentes React: PascalCase (BookCard, ChapterReader)
•	Arquivos de componente: kebab-case (book-card.tsx)
•	Rotas da API: kebab-case (/api/v1/author-profile)

Convenções de segurança:

•	Nunca retornar password_hash em nenhuma resposta da API
•	Validar e sanitizar todo input antes de salvar no banco
•	Rate limiting em todas as rotas de auth
•	CORS configurado para aceitar apenas os domínios da plataforma
•	Todas as senhas com bcrypt (salt rounds: 12)
•	Conteúdo dos capítulos deve ser sanitizado (proteção contra XSS)
